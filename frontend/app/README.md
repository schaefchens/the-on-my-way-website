# @omw/app: the traveler app (Android first)

Expo SDK 58 (React Native 0.88, React 19.3.0, Hermes, New Architecture only), expo-router,
TypeScript strict, Lingui (en source, de, pseudo-ar). Plan and decisions:
`.cache/design-app/app-plan.md` (revision 2) and `owner-decisions.md` (they win).

Phase v0.5 runs **archive-only** (Q8 a): entries go phone → API inbox → home archive, nothing is
published. Uploads default to automatic, Wi-Fi only, roaming off (Q6 c); photo and video
originals go to the archive too (Q2 c).

## Commands (repo root)

```sh
source scripts/app/env.sh                    # SDK, JDK 17, AVD home, shared pnpm store, PATH
pnpm install                                 # with the env above, from any worktree
pnpm --filter @omw/app typecheck             # app + node scripts + tests
pnpm --filter @omw/app test                  # Vitest + jest-expo
pnpm --filter @omw/app i18n:extract          # update src/locales/*/messages.po
pnpm --filter @omw/app tokens[:check]        # re-mirror the design tokens from frontend/shared
scripts/app/build-fonts.sh [--check]         # rebuild assets/fonts from the site's font files

# debug build (needs ≥ 5 GB free disk; android/ is ~1 GB, delete it afterwards)
cd frontend/app && CI=1 npx expo prebuild --platform android --no-install
cd android && ./gradlew assembleDebug -PreactNativeArchitectures=arm64-v8a

# run on our emulator (one emulator at a time; the script holds the lock)
scripts/app/with-emulator.sh -- adb install -r frontend/app/android/app/build/outputs/apk/debug/app-debug.apk
(cd frontend/app && CI=1 npx expo start --port 8081) &        # Metro for the debug build
scripts/app/with-emulator.sh -- sh -c 'adb reverse tcp:8081 tcp:8081 && adb shell am start -n app.omw.traveler/.MainActivity'
pnpm --filter @omw/app e2e                   # Maestro flows (needs Metro on 8081 for a debug build; logs stay in .cache)
# one flow, or a tag:  …/maestro test --include-tags main .maestro   (screens: --include-tags screens)

# release build + the archive-only end-to-end run (no Metro needed)
scripts/app/release.sh --apk --api-base-url http://127.0.0.1:8080   # emulator build, ~4 min
scripts/app/e2e.sh                                                  # ~15 min, see below
```

Backend calls in development go to the local PHP API through `adb reverse tcp:8080 tcp:8080`
(`OMW_API_BASE_URL`, default `http://127.0.0.1:8080`): **never** to the live hosts. A debug build
signed with the debug key and a release build signed with the upload key can't replace each
other: `adb uninstall app.omw.traveler` first.

## Release builds (`scripts/app/release.sh`)

```sh
scripts/app/release.sh --create-upload-key                         # once; never overwrites
scripts/app/release.sh --aab --api-base-url https://<api host>     # bundle for Google Play
scripts/app/release.sh --apk --api-base-url http://127.0.0.1:8080  # emulator test build
scripts/app/release.sh --verify <file.aab|file.apk>                # signer + 16 KB + permissions
```

- **R8** (code shrinking and obfuscation) and resource shrinking are on for release builds
  (`expo-build-properties` in `app.config.ts`); Hermes bytecode as usual.
- **Signing:** the upload key lives in `.secrets/` of the checkout (git-ignored, mode 600):
  `omw-upload.p12` (PKCS12, RSA 4096, valid until 2054), `omw-upload.properties` (its password)
  and the public `omw-upload-cert.pem`. Gradle reads the properties file itself
  (`OMW_UPLOAD_KEYSTORE_PROPERTIES`, set by the script); nothing prints a password and nothing
  secret lands in the generated `android/`. A release build without it stays unsigned, never
  debug-signed. **Back up the .p12 and the .properties together** (e.g. in the password manager):
  with Play App Signing a lost upload key can be reset through Play support, but that takes days.
  After merging this branch into the main checkout, move the three files to its `.secrets/` (or
  point `OMW_UPLOAD_KEY_DIR` at them).
- **The API base is built in** and must be `https://` (pairing links never change it). Only the
  emulator build may use `http://127.0.0.1:8080`; just that build allows cleartext traffic.
- **Versions:** `versionName` 0.5.0 (Play shows it); `versionCode` = minutes since 2026-01-01 UTC
  (always increasing); the build's date + git SHA (`0.5.0-YYYYMMDD-<sha>[-dirty]`) is shown in
  Settings and sent with every entry (`client.app`).
- **ABIs:** the AAB carries arm64-v8a and armeabi-v7a (`--abis` to change), the emulator APK
  arm64-v8a only.
- **Checks after every build** (`scripts/app/check-artifact.py`): signed with the upload key; every
  64-bit native library has 16 KiB-aligned ELF LOAD segments (Play's 16 KB page-size rule; APK:
  also `zipalign -P 16`); no VIBRATE, location, READ_MEDIA_* or SYSTEM_ALERT_WINDOW in the
  manifest; sizes. The report is written next to the artifact (`.json`).
- Output: `.cache/app-release/omw-traveler-<versionName>-<versionCode>[-emulator|-placeholder-api].{aab,apk}`.
  `frontend/app/android` is removed afterwards (`--keep-android` keeps it).

## Google Play internal testing: the owner's steps

Owner decisions Q7 a (Play internal testing; the accounts exist) and A1. Do these in order:

1. **Decide the applicationId** (now the neutral `app.omw.traveler`). It can never change after the
   first upload. To change it, build with `OMW_ANDROID_PACKAGE=<id>`.
2. **Deploy the API with the app inbox** (this branch: migration `0050_app_inbox.sql`, the
   `/api/v1/app/*` routes) with `scripts/deploy-api.ts`, and set `APP_INBOX_MAX_BYTES` to about
   10 % of the hosting quota (video originals, Q2 c), `APP_TRANSFER_SLOTS` after the worker probe.
   Check that the host passes `PATCH` and `HEAD` through to PHP. The home backend keeps
   `APP_PUBLISH` off (archive-only, Q8 a).
3. **Build the bundle** for that API: `scripts/app/release.sh --aab --api-base-url https://<api host>`
   (3–7 min; the host is the backend's `API_BASE_URL`). The `-placeholder-api` bundle in
   `.cache/app-release/` was built without the real host (it lives only in `.env`) and can't pair:
   don't upload it.
4. **Play Console → Create app**: name "On My Way", app, free; accept the declarations.
5. **Testing → Internal testing → Create new release.** On the first release, Play asks how to
   sign: keep **"Let Google manage and protect your app signing key"** (Play App Signing; the key
   of the first upload becomes the upload key). Upload the `.aab`, add a short release note, save,
   review, **roll out to internal testing**. Play may ask for the upload certificate
   (`.secrets/omw-upload-cert.pem`) only if you choose to register the upload key yourself.
6. **Testers:** create an e-mail list with her Google account, add it to the internal track, copy
   the **opt-in link** and send it to her. On her phone: open the link, accept, install from Play.
   Updates then come through Play (each new upload needs a higher versionCode; the script does
   that).
7. **App content** (Policy → App content), as far as Play asks before an internal rollout:
   privacy policy URL, Data safety (photos, videos, audio and text she uploads to her own site;
   no location, no ads), content rating, target audience, and the **foreground service**
   declaration. The app's only foreground service is the video export (`MediaExportService`):
   `dataSync` on Android 14 and older and `mediaProcessing` on Android 15+, for "exporting a
   trimmed video on the phone, started by her Share" (the explanation and demo video should show
   exactly that). **Uploads are no foreground service:** they run as user-initiated data transfer
   jobs (`RUN_USER_INITIATED_JOBS`, Android 14+) or WorkManager workers. [check in the Console:
   which of these internal testing already requires]
8. **Connect her phone:** in the admin, Settings → "Connect a phone" → she opens the link or types
   the code in the app. Then Settings in the app: check "Upload only on Wi-Fi" (on by default)
   and the battery card for her phone's brand.

Production access is not needed for internal testing (new personal developer accounts need 12
testers over 14 days only for production).

## End-to-end run on the emulator (`scripts/app/e2e.sh`)

The repeatable proof of v0.5 archive-only: the release build on our emulator, the local PHP API
(`php -S`, throwaway state), the home backend in fixture mode with `APP_PUBLISH=false` and one
local publish target, and between phone and API a deliberately bad link
(`scripts/app/e2e-proxy.mjs`: throttle, delay, a drop every N bytes, offline; it logs every
request). `adb reverse` traffic does not pass the emulator's radio, so the proxy is the bad link;
airplane mode and Wi-Fi/mobile data are the emulator's own, and the uploader decides from them.
The run takes the emulator lock, needs ≥ 5 GB free and writes `.cache/app-e2e/<run>/` (e2e.log,
summary.md, proxy.jsonl, screenshots). Steps and checks: see the script's header. Latest run:
[`e2e-log.md`](e2e-log.md).

## When something goes wrong (review fixes, 2026-11-22)

- **Undo** ("Shared · Undo", 8 s) works in every upload state and brings back the draft. The draft
  gets a new id for the API (the outbox's `wireId`; the folder keeps its id), because the API keeps
  an id's first content for good, also once withdrawn. The old id is **withdrawn durably**: the
  manifest keeps it until `Uploader.withdraw` has it, and the native uploader then sends the
  `DELETE` before any upload, paced and retried (also without the app), unless the API provably
  never got it. An enqueue that races the Undo is refused, so an undone moment never goes up.
- **Needs you:** "Try again" sends the moment again under a new id (and withdraws the old one); a
  prepared file that is gone is prepared again from the source. "Remove" asks once, withdraws
  the moment from the API and deletes it from the phone.
- **Connected again** (a Disconnect after a false alarm, a token that expired): the app sends its
  install id with the pairing, and the API hands the new token the install's earlier entries, so
  uploads continue at their offsets. Another phone still sees only its own entries.
- **Order:** the media and preview of every moment go before any original, so today's photos
  never wait behind yesterday's video original.
- **The API's disk budget:** entries that saw no upload for 72 h give their reservation back
  (a phone that comes back sends them again).
- **Clock changes:** a wait after a server's `Retry-After` never grows when the phone's clock is
  set back.

## Open checks on her real phone

These need her phone (or the same model) and can't be done on the emulator:

- **OEM background limits:** task killers, battery savers, swipe-away as force-stop, the right
  battery settings path for her brand (the OEM card); whether a killed upload comes back by itself
  (on the API 36 emulator the system did not restart it for minutes; the WorkManager backup is due
  after 15 minutes; opening the app always resumes it).
- **Roaming per SIM/eSIM:** how her SIM reports roaming abroad, and the "Allow on this SIM" card.
- **Real camera files:** HEIC/HDR/10-bit video (tone mapping to SDR is implemented but untested),
  odd rotations, 60 fps, EXIF days of gallery photos; real originals are 3–100 MB (the emulator's
  test pattern gives ~1 MB), so check `APP_INBOX_MAX_BYTES` and the Wi-Fi-only default with them.
- **Pinch zoom and hold-to-record** (not scriptable), the microphone level (the emulator records
  silence), how the haptics feel.
- **The UIDT notification and its permission prompt**, the app lock with her fingerprint/face.
- **3-button navigation:** a light strip under the dark camera/editor screens (needs
  expo-navigation-bar or a window flag; gesture navigation is fine).
- **Play install path:** the opt-in link, install and an update through Play.

## Decisions taken in the foundation

- **pnpm, isolated linker, no workspace-wide changes.** Expo 58 supports isolated installs;
  `expo/metro-config` sets the watch folders. Every native module is a direct dependency here.
  React 19.3.0 (RN's pin) lives beside the web apps' 19.3.1. `react-dom` 19.3.0 is pinned as a
  dev dependency only to satisfy expo's peer.
- **Contracts from source.** Metro gets the `@omw/source` condition and a `./x.js` → `./x.ts`
  fallback for `packages/*/src`. TypeScript uses the same `customConditions`.
- **zod on Hermes** runs with `z.config({ jitless: true })`. Web Crypto is not available in
  Hermes, so `publicIdForSourceKey`/`appEntryHash` must not be called in the app (sha256 comes
  from native code or expo-crypto).
- **Fonts:** static TTF instances of the site's own files (latin + latin-ext + vietnamese merged):
  Fraunces SOFT 600, Nunito 400/700/800, Playpen Sans 400/500, Calistoga, Courier Prime 700,
  Exo 2 800. Embedded by the expo-font config plugin as Android font families, so
  `fontFamily: 'Nunito', fontWeight: '800'` works. WhatsApp's `SYSTEM*` fonts stay the phone's own.
- **Tokens:** a generated JSON snapshot of `frontend/shared` (colours for dawn/dusk, radii,
  spacing, shadows as RN `boxShadow`, Motion springs as stiffness/damping with mass 1), with a
  staleness test, instead of importing `@omw/ui` (DOM, Tailwind, motion).
- **Haptics** only through Android's own constants (`haptic()` in omw-native); no `VIBRATE`.
- **Pairing links never carry the API base**: a stranger's `omw://` link must not redirect her
  uploads. The base comes from the build.
- **applicationId** `app.omw.traveler` (neutral; `OMW_ANDROID_PACKAGE`). Decide the final id before
  the first Play upload: it can never change afterwards.
